## 3. Root Cause of Every Problem

1. **White Screen Root Cause**:
   - **File**: `frontend/src/pages/CameraPreview.jsx`, line 444.
   - **Code**: `<span className="meta-val">{stats?.tracks || 0} active</span>`
   - **Mechanism**: The backend `stats` payload returns `tracks` as a list of track objects (`[{track_id: ..., class_name: ...}]`), not an integer count. In React 18/19, rendering a plain JavaScript object directly into JSX throws an uncaught TypeError: `Objects are not valid as a React child (found: object with keys {track_id, class_name, ...})`. Because there was no top-level React Error Boundary, React completely unmounted the entire DOM root, producing a permanent blank white screen.
2. **Missing Recordings Root Cause**:
   - **File**: `deepvision_django/apps/core/media_service.py`, `safe_resolve_recording()`.
   - **Mechanism**: Anomaly clips generated by the surveillance engine were stored under `instance/evidence/camera_X/`. The database recorded `file_path = evidence/camera_3/clip_....mp4`. When `safe_resolve_recording(recording)` was invoked, it strictly checked `settings.RECORDING_STORAGE_PATH` (`instance/recordings/`), resulting in `resolved_path is None`, HTTP 404 on media endpoints, and `file_exists: false` in JSON APIs.
   - Furthermore, `Recordings.jsx` never rendered page navigation buttons, so the user was hard-capped to seeing only page 1 (20 items).
3. **Browser Automation Blockage Root Cause**:
   - Playwright's external release package server rejected automated driver downloads. However, standard Google Chrome (`C:\Program Files\Google\Chrome\Application\chrome.exe`) was already present on the Windows workstation. Playwright was attempting an unnecessary binary download rather than binding to local browser infrastructure.
4. **Offline IP Camera Handling Root Cause**:
   - `Cameras.jsx` and `Dashboard.jsx` unconditionally mounted `<img>` tags pointing to snapshot endpoints even when `camera.status !== 'online'`.

## 4. Exact Fixes

1. **Type-Safe HUD Track Counter & Error Boundary**:
   - Updated `CameraPreview.jsx` line 444 to safely compute length:
     ```jsx
     {Array.isArray(stats?.tracks) ? stats.tracks.length : (typeof stats?.tracks === 'number' ? stats.tracks : 0)} active
     ```
   - Created `frontend/src/components/common/ErrorBoundary.jsx` and wrapped all routes in `App.jsx`. If any component throws an uncaught rendering error, a sleek SOC-themed error card is displayed instead of unmounting the SPA root.
   - Added an in-monitor offline banner overlay in `CameraPreview.jsx` when camera status is offline.
2. **Multi-Directory Recording Resolver & Full Pagination**:
   - Enhanced `safe_resolve_recording()` in `media_service.py` to evaluate both `instance/recordings/` and `instance/evidence/` (as well as `instance/` root) with path traversal validation:
     ```python
     candidate_bases = [
         Path(settings.RECORDING_STORAGE_PATH).resolve(),
         (Path(settings.BASE_DIR).parent / "instance" / "recordings").resolve(),
         (Path(settings.BASE_DIR).parent / "instance" / "evidence").resolve(),
         (Path(settings.BASE_DIR).parent / "instance").resolve(),
     ]
     ```
   - Updated `api_recordings_list` in `apps/core/api.py` to support `type=continuous|anomaly`, `camera_id`, `has_next`, `has_previous`, `num_pages`, and `total_count`.
   - Updated `Recordings.jsx` with full pagination (First, Prev, Page indicator, Next, Last), type filter tabs (All, Continuous, Anomalies), format fallback recovery, and archived indicator for purged 0-byte clips.
3. **Direct Chrome DevTools Protocol Automation**:
   - Built `verification/run_browser_suite.mjs` using native Node 24 `WebSocket` to drive the locally installed Google Chrome via remote debugging port 9222.
   - Fully executed all required user interactions without downloading external drivers.
4. **Offline IP Camera Guard**:
   - In `Cameras.jsx` and `Dashboard.jsx`, added conditional checks ensuring that only online cameras render live snapshot/stream image elements. Offline cameras display the `.camera-placeholder` with a clean warning badge.
5. **Cases API Contract Alignment**:
   - Added support for `status` (mapping `investigating` to `in_progress`), `priority`, and `search`/`q` to `api_cases_list`.
